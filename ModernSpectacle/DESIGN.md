# ModernSpectacle 设计：窗口管理 + Chrome 管理

状态：草案，2026-10-21。第一步只做 Chrome 标签监控（0.2），后面的阶段按顺序推进。

## 1. 目标

- 窗口管理：用键盘快捷键移动、缩放、平铺窗口；按「工作情境」一键智能排列。
- Chrome 管理：看清每个标签和渲染进程在消耗什么；失控的 JS 冻结而不是杀掉；长时间不用的标签释放内存但保留在标签栏；需要并排看的标签拆成独立窗口一起排。
- 自身开销：常驻内存 ≤ 10 MB，空闲时零唤醒，不联网（接入 Claude API 需在设置里明确开启）。

## 2. 两个绕不开的系统限制

1. macOS 不允许一个 App 释放另一个 App 的内存。真正能回收内存的只有：让进程自己释放（Chrome 的标签丢弃）、或让进程退出。「冻结」（SIGSTOP）只停 CPU，内存不释放但停止增长，之后由内核按最久未用的顺序压缩。
2. macOS 只能排列窗口，不能排列标签页。要并排看两个标签，先把一个拆成独立窗口。

Chrome 扩展 API 正好补上这两个缺口：`chrome.tabs.discard` 精确释放单个标签的内存，`chrome.windows.create({tabId})` 把标签拆成新窗口。所以 Chrome 管理的核心是一个我们自己的扩展，不是 AppleScript，也不是「自动化」权限。

## 3. 架构

```
ModernSpectacle.app（AppKit，常驻 ≤ 10 MB）
├─ Core（纯 Swift，可单测、可回放）
│   ├─ 事件日志：窗口焦点、App 切换、标签活动、空闲、内存压力、我们的操作和用户反应
│   ├─ 情境模型：哪些窗口/标签总是一起用
│   ├─ 摆放偏好：每个窗口在每个情境里习惯放哪
│   ├─ 布局求解：无重叠分配
│   └─ 决策引擎：输入近期历史，输出动作列表（Claude API 或本地启发式）+ 本地安全校验
├─ Services
│   ├─ AXWindowClient：读写任意 App 的窗口
│   ├─ HotKeyCenter：全局快捷键（Carbon，唯一的 C 桥）
│   ├─ ProcessStats：每个进程的物理内存、CPU（libproc，无需 root）
│   ├─ ProcessControl：SIGSTOP / SIGCONT / 限速（交替暂停与继续）
│   ├─ IdleMonitor、MemoryPressure（dispatch source）、AudioActivity（CoreAudio 进程列表）
│   └─ ChromeBridge：与 Chrome 扩展通信
├─ ChromeNativeHost（独立小可执行文件，由 Chrome 启动，stdio ↔ Unix socket 转发给 App）
└─ ChromeExtension（Manifest V3，随 App 一起分发）
    ├─ 观察：标签列表、标题/URL 变化、激活、音频、丢弃状态、最后访问时间、窗口位置
    ├─ 内容脚本：检测页面里有没有用户改过未提交的表单
    └─ 动作：丢弃标签、恢复标签、标签拆成新窗口、设置 Chrome 窗口位置和大小
```

### 3.1 Chrome 扩展与 App 的连接

- 扩展通过 Native Messaging 启动 `ChromeNativeHost`，它只做转发。App 不在运行时，host 丢弃消息。
- Native Messaging 的注册文件由 App 写到 `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/xyz.alvumo.modernspectacle.json`，`path` 指向 App 包内的 host，`allowed_origins` 只包含我们扩展的 ID。
- 扩展的 `manifest.json` 带固定 `key`，这样无论从哪个路径加载，扩展 ID 都不变。
- 安装流程：菜单里点「安装 Chrome 扩展」→ App 打开 `chrome://extensions` 并给出三步说明（开发者模式 → 加载已解压 → 选 App 包内的 ChromeExtension 目录）。个人使用先这样；之后可以发到 Chrome Web Store（不公开列出）去掉开发者模式提示。
- MV3 的 service worker 在有打开的 native 端口时不会被挂起；断线自动重连，带退避。

### 3.2 两个层次的 Chrome 数据，以及它们怎么对上

| 层次 | 来源 | 能看到 | 能做 |
|---|---|---|---|
| 标签 | 扩展 | 标题、域名、是否激活、最后访问、是否播放声音、是否已丢弃、是否有未提交表单 | 丢弃、恢复、拆窗、摆放窗口 |
| 进程 | App（libproc） | 每个渲染进程的内存、CPU、启动时间 | 限速、冻结、解冻、结束 |

Chrome 稳定版没有公开「标签 ↔ 渲染进程」的映射（`chrome.processes` 只在 dev 渠道可用）。处理办法：

- 不依赖精确映射。标签层的决定（丢弃哪些）只用标签层数据；进程层的决定（冻结哪个）只用进程层数据。
- 用两条线索学习映射：渲染进程的启动时间和标签的创建时间相近；丢弃某个标签时若恰好有一个渲染进程退出，它们就是一对。学到的映射用于显示「疑似标签」，不用于强制决策。
- 解冻不需要映射：只要 Chrome 回到前台或切换了标签（扩展的 `onActivated` 事件），解冻全部冻结的渲染进程。代价是几毫秒。

## 4. Chrome 管理：动作梯度

| 问题 | 动作 | 效果 | 可逆性 |
|---|---|---|---|
| 某个渲染进程 CPU 失控 | 限速：每秒只让它跑 100 毫秒 | CPU 压到 10%，连接不断，页面还能慢慢动 | 自动 |
| 仍失控 / 用户不在 | 冻结该渲染进程 | 零 CPU，内存停止增长 | 切回 Chrome 或切标签时立即解冻 |
| 用户长时间离开 | 冻结整个 Chrome 进程树（先隐藏窗口） | 整个 Chrome 零 CPU | 点 Dock、⌘Tab、任何键鼠活动后解冻 |
| 标签长期不用 / 内存紧张 | 丢弃标签（`chrome.tabs.discard`） | 该标签内存全部回收，标签仍在标签栏，点击时重新加载 | 点击即恢复 |
| 渲染进程内存失控且系统内存紧张 | 结束该渲染进程 | 内存回收；该标签显示「崩溃」，网址保留，点击重新加载 | 点击即恢复 |

顺序原则：内存紧张时先让进程收到系统的压力通知清缓存，再冻结；冻结中的进程收不到通知。

### 4.1 本地强制的安全线（唯一一组写死的规则）

- 正在播放或录制声音的进程不冻结、不丢弃其标签。
- 前台窗口、当前激活的标签不动。
- 有未提交表单的标签不丢弃（内容脚本检测）。
- 正在下载时不冻结整个 Chrome（扩展 `chrome.downloads` 可查）。
- 用户放进「永不打扰」的站点和 App 绝对不碰。
- 关机、注销、睡眠前解冻全部；App 自己退出或崩溃前解冻全部；冻结清单同时写盘，重启后先按清单解冻。

### 4.2 失控的判定不写死阈值

记录每个后台渲染进程平时的 CPU 分布和内存增长率。某个进程持续远高于历史分布、或内存连续数分钟单向增长，才算失控。用户手动解冻过的情形会抬高下次判定的门槛。

## 5. 决策引擎

两种后端，接口相同：输入近期历史，输出动作列表。

- **Claude API（可选，需开启）**：把近期历史整理成一张紧凑的表：每个大进程一行（名字、所属 App、内存、近 5 分钟和 1 小时 CPU、增长率、最后前台时间、是否在放声音），每个标签一行（域名、标题、最后访问、是否已丢弃、是否有表单），系统状态（空闲时长、内存压力、时段），最近 20 条「我们做了什么、用户怎么反应」。模型返回固定格式的 JSON：动作、原因、信心值、下次检查时间。模型还维护一小段关于这个用户的笔记（存本地，每次带上）。固定部分走 prompt caching，每次约 3 千 token 新内容，一天 10 到 30 次调用。Swift 没有官方 SDK，用 URLSession 直接调 HTTP。API Key 存钥匙串。
- **本地启发式（默认）**：按最后访问时间、空闲时长、内存压力排序，保守执行。断网或 API 出错时也退回这里，或者什么都不做。

不管哪种后端，输出都先过第 4.1 节的安全校验再执行。快捷键移窗口不经过决策引擎，纯本地，≤ 50 毫秒。

发给 API 的内容由用户选择：只发进程名和数字；或加上域名和标题。页面内容永远不发。

## 6. 窗口管理

- 基础：现有的 18 个动作和快捷键不变，`WindowLayoutCalculator` 复用。
- 情境：短时间内来回切换的窗口和标签聚成一组，带时间衰减。冷启动用 App 的 `LSApplicationCategoryType` 和标题相似度做弱先验。
- 摆放偏好：按（App、情境、显示器配置）记录用户手动摆放的位置和大小；我们排完用户又挪动，是权重最高的纠正信号。
- 智能排列（一个快捷键）：判断当前情境 → 该情境的窗口按偏好位置做无重叠分配 → 其他窗口按习惯留下、最小化或移到另一块屏幕。Chrome 窗口通过扩展精确摆放，其他 App 通过辅助功能。
- 标签拆分：同情境里相关的标签（同域名、同项目名、常一起看）通过扩展拆成独立窗口，并入排列。
- Chrome 窗口与辅助功能看到的窗口通过标题和位置对应起来，两边数据合并。

## 7. 可见与可撤销

- 菜单栏显示 Chrome 概况：标签数（已丢弃数）、总内存、CPU 最高的渲染进程。
- 「Chrome」面板：标签按闲置时间排序，每行有丢弃/恢复/拆窗；渲染进程列表显示内存、CPU、疑似标签，每行有限速/冻结/解冻。
- 「活动」面板：每条自动操作带原因和一键撤销。
- 每周汇报：释放了多少、误判几次。误判率是评估模型改动的唯一标准。
- 隐私：不联网是默认。URL 只存域名，标题只在内存里用，落盘的是哈希后的词。设置里可导出、清空全部学习数据。

## 8. 性能预算

- 常驻内存 ≤ 10 MB（当前 14 MB）。只用 AppKit，设置和面板按需创建。
- 空闲零唤醒：数据全部来自系统通知、AX 观察者、扩展推送；进程统计只在决策时采样。
- 快捷键到窗口动起来 ≤ 50 毫秒（我们这边）；8 个窗口智能排列 ≤ 300 毫秒。
- 事件日志用系统 SQLite，自动修剪，每月增长 < 5 MB。日志可回放，用于离线评估模型改动。
